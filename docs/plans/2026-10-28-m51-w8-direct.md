# M5.1 Wave 8 Direct Commits — the review orchestrator writes the review summary straight to its kept path (#9198) Implementation Plan

**Goal:**
- The root problem: review-sdlc keeps its machine-readable review summary for ship-sdlc by a Bash `cp` out of the `/tmp` diff dir. A headless `--permission-mode dontAsk` run denies that `cp` (B6r2), so a standalone review never leaves the file.
- The fix (OWNER `owner-w8.md`; ruling w8-preflight Q1–Q8):
  - the review orchestrator writes `review-summary.json` in ONE Write, with its Write tool, straight to `summary_copy_path` (the manifest field it already reads);
  - review-sdlc drops the two-call copy from Step 2 and instead Reads the file after a `Review complete` return, with a stale-file guard (`commentPath` must equal this run's `Comment file:` line);
  - a missing or stale file reports `Review summary missing: <summary_copy_path>` and stops, keeping `diff_dir`.
- Spec-consequence commits come FIRST (review-sdlc P11, G3 and a history row; ship-sdlc R6 wording), then the text commits, then C-docs last.

**Architecture:** The executor applies this plan directly, task by task. There is no ship run and no execute run on this branch (ruling w8-preflight Shape: "direct commits, no ship run"). Task 7 commits nothing; it runs the final-head checks. Each body file is written with the Write tool under `$TMPDIR` (outside the repo; see Deviations for an empty `$TMPDIR`), with NO `Co-Authored-By` line, and is removed after its commit by its resolved path.

## Context

**What problem does this change solve?**

- review-sdlc ends every review by keeping a small JSON file, the review summary (`review-summary.json`: verdict and finding counts). ship-sdlc's review gate (the step that decides whether to run received-review-sdlc) reads it from `.sdlc/execution/review-summary-<slug>.json` in the main worktree.
- Today the review orchestrator (the subagent that runs the review) writes that file into the temporary diff dir under `/tmp`. Then review-sdlc copies it to the kept path with two Bash calls, `mkdir -p` and `cp`.
- In a headless run with `--permission-mode dontAsk`, Claude Code denied that `cp`, although `Bash(cp:*)` was allowed (B6r2). So no standalone run has yet left the file.
- The 0.36.3 CHANGELOG claimed that a headless standalone review leaves the file. That claim did not hold.

**What prompted this change now?**

- The B6r2 re-check (`e2e-b6r2-result.md`) showed the wave-7 behaviour working as designed, except for the denied `cp`.
- The owner decided "Fix wave 8 first" (`owner-w8.md`), before the plugin swap, as release v0.36.4.
- The arbiter ruled the pre-flight questions (ruling w8-preflight): use the existing manifest field, keep `diff_dir` under `/tmp`, one Write, a Read check with a stale-file guard, no new spec id, no new test case.

**What does success look like?**

- The spec states the new behaviour first: P11 says the orchestrator writes the file straight to `summary_copy_path` and names the stale-file guard; G3 names the one stop that keeps `diff_dir`; ship-sdlc R6 no longer says "copied".
- review-sdlc's SKILL.md contains no `mkdir -p '…'` or `cp '…'` line: `grep -nE "^(cp|mkdir -p) '"` goes from 2 hits to 0.
- The orchestrator returns the same summary format, with `Summary file:` and `Summary copy path:` both naming the kept path.
- `review.js` changes by exactly one comment line. Every validator stays green. The exec counts stay 984 / 58.
- After the merge, the owner's ONE B6 re-check observes the file (owner-w8; not part of this plan).

## Key Decisions

- **KD-1 — One commit per spec, not one for both.**
  - The two specs belong to two skills.
  - One commit each gives each commit a correct `<skill>` in its subject (`review-sdlc` / `ship-sdlc`), as the repository convention `type(#issue): skill - description` asks.
  - P-5 stays SAME per spec either way, and the order is still spec-first.

- **KD-2 — D-write: one Write, straight to `summary_copy_path`; both return lines carry that value.**
  - The orchestrator already reads the manifest field (`:178`), so the dispatch prompt does not change (ruling Q1).
  - No summary file goes into `diff_dir` any more (ruling Q4). So nothing is left orphaned in `/tmp`, and the file the skill checks is exactly the file ship reads.
  - `Summary file:` keeps its line and gets the same value as `Summary copy path:`. Step 3's parser and the return format stay the same.
  - `commentPath` in the JSON stays the absolute `review-comment.md` path in `diff_dir`; that is what the guard compares.

- **KD-3 — D-check: the skill Reads the file and compares `commentPath` with the `Comment file:` line.**
  - The Read tool works in dontAsk; a Bash `test -f` might be denied like `cp` was (ruling Q5).
  - A file left by an EARLIER review on the same branch already sits at the kept path. A bare existence check would pass on stale data. `diff_dir` is a fresh temp dir per run, so only this run's file has this run's `commentPath` (ruling Q4 guard).
  - The comparison is an exact string match of two absolute paths, both written by the orchestrator from the same value.
  - On failure the skill shows `Review summary missing: <summary_copy_path>` and the comment path, and stops. Step 6 does not run, so `diff_dir` (which holds the finished `review-comment.md`) is kept. The failure path adds no `rm` and no other command (read twice for this plan, wave-7 lesson).
  - No Read step is added before the orchestrator's Write: the planner probe showed the Write tool overwrites an un-Read file. If a headless Write is refused anyway, the guard turns that into the visible stop.

- **KD-4 — D-spec: amend P11 and G3 in place; no new id; C13 unchanged.**
  - P11 is the summary's contract, so the new writer, the no-Bash rule and the stale-file guard go there (ruling Q6, Q4 "Name it in P11").
  - G3 says `diff_dir` is removed "after the terminal branch (including failures)". The summary-missing stop keeps it, so G3 names that one exception. The other #9197 stops stay out of scope.
  - C13 is about REFERENCE.md; the owner's "C13 as needed" is not needed (ruling Q6).
  - The history row follows the table's existing form `| <id> | (issue #<n>) |`.
  - ship-sdlc R6: "copied to" becomes "kept at". The path, the mtime rule and the gate logic do not change.

- **KD-5 — D-docs: the user doc row says who writes the file and what the check does.**
  - `docs/skills/review-sdlc.md:391` drops "copied from `diff_dir` right after …" and names the orchestrator's Write, the check and the `Review summary missing` stop.
  - `reference.md:50` names the orchestrator as the writer. `review.js:662` changes its comment only.

- **KD-6 — D-verify: the full exec runs happen once, at the final head (Task 7).**
  - No exec case greps the changed text, and no consumer grep finds the removed strings in `tests/promptfoo` (C9). So no per-commit targeted promptfoo run is needed.
  - The named regression set (ruling Q3: 17+1 cases) is inside the T1 full exec run, so it needs no separate run.
  - The cheap validators (check-consistency, check-docs-consistency, the spec-shape block) run after every task.
  - D-beh: none (ruling Q8: "none. The B6 re-check after the merge is the observation (owner-w8)"). This plan proposes no behavioural case and runs none.

- **KD-7 — Review cover (re-w2-review-coverage).** Changed file types and the review-sdlc dimensions that see them (from each `.sdlc/review-dimensions/*.md` `triggers` / `skip-when`):

  | Changed file | Dimensions that see it |
  |---|---|
  | `plugins/sdlc-utilities/skills/review-sdlc/SKILL.md` | docs-skill-sync, hook-readiness, runtime-contract, script-resolution, security-review, skill-architecture, spec-compliance |
  | `plugins/sdlc-utilities/agents/review-orchestrator.md` | skill-architecture only |
  | `plugins/sdlc-utilities/skills/ship-sdlc/reference.md` | security-review only |
  | `plugins/sdlc-utilities/scripts/skill/review.js` | code-quality, security-review (`**/scripts/*.js` of hook-readiness / runtime-contract does not match `scripts/skill/`) |
  | `docs/specs/review-sdlc.md`, `docs/specs/ship-sdlc.md` | spec-compliance |
  | `docs/skills/review-sdlc.md` | docs-skill-sync |
  | `docs/plans/2026-10-28-m51-w8-direct.md`, `site/src/content-source/**` | none (no trigger matches) |
  | `schemas/review-summary.schema.json` | security-review (`schemas/**/*.json`) |
  | release files `plugins/sdlc-utilities/.claude-plugin/plugin.json`, `CHANGELOG.md` | release-consistency |

  - Caps: security-review has `max-files: 50`; this PR changes about 15 files, so no cap can drop a changed file. No other matching dimension has a cap.
  - Gap: the orchestrator is seen by one dimension, and spec-vs-text agreement is seen only by spec-compliance on SKILL.md and the specs. The orchestrator's Opus review and the gate's text checks (Task 3) cover the orchestrator edit.

- **KD-8 — The two harness comments are reported, not edited (needs review).** `ship-review-gate-exec.yaml:3-4` and `run-ship-stepper.js:44,270` say "copied" about the test harness seeding a fixture into the place "review-sdlc leaves it". After this wave review-sdlc's orchestrator still leaves it there, so the text stays true. They do not describe the Step 2 Bash `mkdir`/`cp`. No ruling covers them, so they are not in Files. If the orchestrator reads them as describing the Bash copy, this is a QUESTION for the arbiter, not something this plan decides.

- **Explicit non-goals (not built this wave):** moving `diff_dir` out of `/tmp` (ruling Q2); a `SUMMARY_COPY_PATH:` dispatch line (ruling Q1 (b)); a new spec id such as C14 (ruling Q6 (b)); any review.js or ship.js logic change; the W4.5 summary schema (except its one `description` string, ruling w8-plan Q1 (a)); received-review-sdlc; the other #9197 stops; `.github/instructions/*`; released CHANGELOG entries; any new or changed exec or behavioural case (ruling Q3, Q8); the linked-worktree dontAsk Write (a known limit, ruling Q1).

- **Smallest viable cut:** Tasks 1, 2 and 3 are the fix and its contract. Tasks 4 and 5 are the two Files extensions the ruling accepted, so no surface keeps saying "review-sdlc copies". Task 6 is the mandatory C-docs block.

- **Who fails if this ships wrong:** every review-sdlc user and every ship-sdlc run. A wrong Write path or a wrong guard makes every review stop with `Review summary missing` (visible, and `diff_dir` is kept). A missing file makes ship's review gate dispatch received-review-sdlc with a warning (R6, C17), which is safe but slower.
