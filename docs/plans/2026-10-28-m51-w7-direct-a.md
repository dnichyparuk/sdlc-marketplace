## Context

**What problem does this change solve?**

- review-sdlc copies its machine-readable summary (`review-summary.json`) to the place ship-sdlc reads it from only in its last step, Step 6. A headless standalone run ends after it shows the review, so the copy never happens (STOP 11, B6c: the file existed only in the temp diff dir).
- The review orchestrator (the subagent that runs the review) finds `REFERENCE.md` by a Glob over `~/.claude`. In the e2e run it read the upstream marketplace copy, not the fork's. After the plugin swap, `~/.claude/plugins/` can hold two versions, and the search can pick the wrong one.
- The same class of search appears in setup-dimensions (REFERENCE.md, EXAMPLES.md), in nine error-report lines in six skill files, and in `jira.js` (a home-dir walk for its templates). The repo's own review policy even requires the `~/.claude` search.
- The specs are the contract. So the specs must say the new behaviour before any skill text or script changes (spec-first).

**What prompted this change now?**

- The owner answered Q24 with "(a) Copy early" and placed wave 7 before the plugin swap (`owner-q24.md`).
- The arbiter ruled the class scope (ruling w7-preflight Q1–Q7), version-sdlc and the jira fixture (ruling w7-plan), and the policy source and harden consumers (ruling w7-plan2).

**What does success look like?**

- The four spec files carry the new sentences, with exactly the ids named above added and nothing renumbered.
- validate-spec-shape still lists only received-review and version as LEGACY.
- After Task 5, the three plan files and the four spec site mirrors are committed, and `git status --porcelain` prints nothing, so the ship run can start.

## Key Decisions

- **KD-A1 — review spec wording.** P11's last sentence now says when the copy happens: right after the orchestrator returns its summary, before display, posting or self-fix. It also says the copy runs only on a successful return, and that a missing summary file is reported and the skill stops (ruling w7-preflight Q1, Q2). The alternative, a new R-id for the timing, was rejected: P11 is the one anchor of the copy, and the source says "P11's last sentence". G2 adds "REFERENCE.md path (C13)", so the gate names every dispatch input. `C13` is a new invariant. It continues the numeric C-series of that section, so no id is renumbered.
- **KD-A2 — setup id.** The new id is name-based (`R-plugin-root-refs`), the form the spec uses for ids added after launch. It sits right after R13 because R13 is the sub-flow rule. The alternative was to widen I3 (Integration). That was rejected because I3 only names the file and holds no rules.
- **KD-A3 — jira id.** `R-templates-root` goes in `## Prepare script contract` because it binds `skill/jira.js` itself. It says the cwd fallback is gone. No spec line needs that fallback: R18 names the shipped templates inside the plugin, and the plugin always keeps `scripts/` and `skills/` side by side. The feat plan's KD2 records this decision. The Acceptance bullet states what the exec case checks.
- **KD-A4 — harden sentences without an id.** Only the description of the route changes ("Glob-then-follow" → read and follow `<PLUGIN_ROOT>/skills/error-report-sdlc/SKILL.md`). No new rule appears, so P-5 stays at 73 (ruling w7-plan2 Q2).
- **KD-A5 — C-docs before the ship run.** The plan files and the four spec mirrors are committed before the ship run. The run then starts on a clean tree with its frozen plan in the repo. The doc mirrors that direct-b changes are committed last (direct-b C-docs).
- **KD-A6 — smallest viable cut.** The owner's minimum is the early copy plus the REFERENCE.md resolution. The other surfaces (error-report idiom, jira.js, policy, harden sentences) are in because the owner asked for "every surface of this class" and the arbiter ruled each one in. No spec sentence goes beyond what those rulings name.
- **KD-A7 — who fails if this ships wrong.** Users of a standalone review lose the summary that ship's review gate reads. Users after the swap get a stale REFERENCE.md or jira templates. This repo's own reviewers (Claude review and Copilot) would follow the old policy. The spec sentences are the contract every later task is checked against, so a wrong sentence misleads all of them.
- **KD-A8 — explicit non-goals.** Not built in this wave:
  - `plan.js:176-194` (follow-up #9196);
  - `plan-explore.js`, the `ship.js:781` comment, `.claude/skills/test-report`, `review.js`;
