## Context

**What problem does this change solve?**

- A plan can carry a `**Commit:**` header field: the planned subject of the ship run's commit. Ship forwards it to commit-sdlc as `--subject`.
- At prepare time, ship checks the field against `commit.subjectPattern` and reports an unreadable plan.
- Every later `--after` call recomputes the steps and re-reads the field without the pattern, and it drops any read error. So a field that no longer passes (a config change mid-run, or an unreadable plan) is forwarded, or silently dropped, and commit-sdlc then drafts its own subject. That was PR #41's acceptance note on W8.24 (#9180).

**What prompted this change now?**

- Ruling w4-preflight Q3 granted #9180 (i) and (ii) for waves 4+5. (iii) is follow-up #9185.

**What does success look like?**

- An `--after` call whose plan field fails the pattern exits 1 with an error envelope, and the ledger is byte-identical.
- Every existing ship case still passes.

## Key Decisions

1. **A read or pattern failure stops the `--after` call (D-9180).**
   - Choice: match prepare: error envelope, exit 1, nothing recorded.
   - Alternative: a warning, with the recompute forwarding no subject.
   - Why: a warning would let commit-sdlc draft an unplanned subject, which is the defect #9180 names.
2. **The final `cleanup` call is exempt.**
   - Choice: `if (planCommit.error && after !== 'cleanup')`.
   - Why: no commit step follows `cleanup`, so there is no subject to protect.
     - Failing there would strand a finished pipeline whose plan was edited after the commit.
     - The cleanup-only summary-sidecar unlink (`skill/ship.js:1890-1892`) runs before this check. With the exemption, a failing check never follows that unlink.
   - Other post-commit steps (review, version, pr) are not exempt, on purpose: D-9180 says to match prepare. A plan that becomes unreadable or invalid mid-run stops those calls until it is fixed, and `cleanup` alone is let through so a finished run can close.
   - Found by the plan reviewer (round 1). Accepted, orchestrator decision in question-w4-planreview.md, confirmed by ruling w4-planreview.
3. **One read per call.**
   - `planCommit` is computed once in `runAfter` and its `subject` goes to `computeSteps`.
   - The `branch_prepare` recompute keeps the subject (R-expected-branch-branch-derive is unchanged).

**Non-goals:** the chmod-0 case under root (#9185); any prepare-path change; any new config key.

**Failure audience:** ship-sdlc users whose plan carries a `**Commit:**` field and whose `commit.subjectPattern` or plan file changes during a run.
