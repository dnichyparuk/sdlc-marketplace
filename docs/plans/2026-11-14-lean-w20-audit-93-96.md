**What does success look like?**

- Every hole is denied by the guard, and the commands the brief keeps allowed stay allowed.
- Every drift is fixed, with an exec case where the item asks for one.
- The targeted exec cases pass, and the main-session validators stay green.

## Decisions taken without the owner

- **Fail closed on `-p3` and `-C3`.** The simple `3` rule is the one the brief names. Workers can write `-p 3`.
- **Add the `check-error` case** with a preload in a test wrapper. The fault hook lives only in the test script, not in the plugin.
- **One wrapper script for the new `--check-brief` cases** instead of four inline `node -e` one-liners. The preload text holds quotes, and a one-line YAML string with nested quotes is easy to break.
- **Spec and code in two parallel tasks.** `plan.copyRules` (in `.sdlc/config.json`) makes a task that lists a spec also list the skill's user docs and companions as check-only entries. With those, one spec-plus-code task would list nine files. The R90 text is fixed in Task 1's Contract, so Task 2 can run in the same wave.
- **Check-only copy entries.** Tasks 1 and 4 list the user docs, site copies, `skills-meta.ts` and the skill directories as `Modify: ... — check only`, as waves 16 and 18 did. A grep at HEAD found no user doc that states the changed rules.

## Key Decisions

- **Bare `--` ends option parsing for the `git apply` tests.** Git reads every word after a bare `--` as a file name. So the read-only, write and long-option tests read only the words before it. The escape test (backslash, `$'..'`) still reads every word, because it fails closed and an escaped word after `--` is still odd. Alternative: drop words after `--` from every test. Rejected: it would weaken the fail-closed escape rule.

- **Prefix match for `patch --output`.** An option word starting with `--o` whose name (the part before `=`) is a prefix of `--output` is an output option. Its value is the text after `=`, or else the next word. Every output target must be a scratch path. Alternative: list `--o`, `--ou`, ... `--output` by hand. Rejected: the prefix test is shorter and says the same.

- **Wrapper script over inline `node -e`.** The commit-prepare cases use inline `node -e`. Here the fault preload adds a second quoted layer, so a small script is easier to read and review. It mirrors the existing `run-*.js` test wrappers.

- **Sentinel quotes the live text.** The sentinel checks the strings that the orchestrator agent and SKILL.md hold today (for example "isolation or background"). It does not ask them to change. Alternative: rewrite SKILL.md to say `run_in_background`. Rejected: out of scope, and the spec meaning is the same.

- **Root problem.** The guard's `git apply` and `patch` parsers read option words that git and GNU patch read differently, and three docs or tests drifted from their specs.

- **Who fails if this ships wrong.** Execute workers in every consumer project: a guard that denies too much blocks a worker command the plan needs; a guard that allows too much lets a worker write a file outside its task files (then the R44 `expectedFiles` check fails the wave). The plan-sdlc and ship users read the docs.

- **Smallest viable cut.** Each task maps to one or two brief items; nothing is added beyond them.

- **Non-goals.** No other guard bypass class (bundled `patch` short options such as `-fo X`, `-r`/`--reject-file`, `-b`), no other README drift (F-hooks-readme-r90-drift-3 to -5), no change to plan-explore.js, SKILL.md or the orchestrator agent, no behavioural or headless test run.

- **Workspace modes.** The guard reads only the stdin payload, so it behaves the same under `ship.workspace=branch` and `worktree` (README line 7). The test scripts resolve the repository from their own path. No state file or config read changes.

- **Tracking id, not an issue.** #9387 is an internal register id. The PR body names it with no `Fixes` or `Closes` keyword (project note), so the `pr-link-github-issue` guardrail does not apply.

- **Threat model unchanged (F-73).** R90 already states that the guard is a best-effort filter, with `expectedFiles` under `--strict-files` as the backstop, and lists its accepted gaps. Tasks 1 and 2 keep that text. Reviewers report only gaps outside that list. Bundled short options in `patch` (`-fo X`), `-r`/`--reject-file` and `-b` stay outside this wave (F-worker-guard-apply-patch-option-parsing-4).
