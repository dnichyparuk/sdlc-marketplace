# Audit Fixes for PRs #89-#92 (W16) Implementation Plan

**Commit:** `fix(#9381): guard, specs - unquote git apply and patch args, knobs`
**Goal:** Close six low defects found by the post-merge audit of PRs #89-#92 (todo #9380, ledger F-77 to F-82):
- the worker write guard must read `git apply` and `patch` arguments as the shell does (quoted words kept whole, quotes removed), so two quoted bypasses are denied;

The guard gets one small helper that splits a command segment on the quote-masked text (same character offsets as the real command) and removes quote characters from each word; `gitApplyDenied` and `patchDenied` both use it. The root problem is that the guard reads arguments from the unmasked command with a plain whitespace split, so its word list does not match the shell's word list when a quoted word holds spaces or quote marks.

## Context

**What problem does this change solve?**

- The worker write guard (a hook that stops execute workers from writing files through the shell) lets two quoted forms through. `git -c "user.name=a b --check c" apply y.patch` is allowed, because the guard counts words differently in the masked and the real command. `patch -o /tmp/x "-o" src/a.js < p` is allowed, because the guard does not remove the quotes around the second `-o`.
- Spec R90 and the hooks README describe the `git apply` rule incompletely. They do not say that a write flag (`--apply`, `--index`, `--cached`, `--3way`, `-3`) is denied even with `--check`.
- The ship prepare script rejects a bad `--rebase` value, but no exec case proves it.
- Specs R21 (review-sdlc) and R92 (execute-plan-sdlc) state tuning values. The project rule in `docs/cost-tiers.md` §6 says a spec names each tuning knob and never states its value.

**What prompted this change now?**

The post-merge Opus audit of PRs #89-#92 (2026-11-13) found six low defects. An isolated verifier confirmed each one (todo #9380).

**What does success look like?**

- `classifyCommand` denies both quoted bypasses, and quoted read-only forms such as `git apply "--check" p` stay allowed.
- R90 and the README match the code.
- An exec case covers `--rebase bogus`.
- R21 and R92 name their knobs only; `docs/cost-tiers.md` lists every value; all site copies match byte for byte.

## Research Findings

**Guard (F-guard-apply-patch-unquote-fix-1, -2, -4).** `maskQuotes` (`worker-write-guard.js:41`) keeps the string length: every character inside quotes becomes `_`, and an escape outside quotes becomes two characters. So a character offset in the masked text is the same offset in the real command. A quoted string with spaces is one masked word but several real words. `findCommands(masked, name)` returns `{s, e}` offsets of each command segment. `ddDenied` (`:289-297`) and `isAllowedTarget` (`:262-265`) strip only one leading or trailing quote (F-guard-apply-patch-unquote-fix-3).

**Exec cases (F-guard-apply-patch-unquote-fix-5).** `tests/promptfoo/datasets/worker-write-guard-exec.yaml` holds 85 cases; the last id is `(l65)` at `:893` (the explore brief said `l30`; that is wrong). ## Decisions taken without the owner

- **One helper for both rules.** `gitApplyDenied` and `patchDenied` share a new `argWords(cmd, masked, s, e)` helper. Alternative: fix each rule inline. Two copies of the split-and-unquote logic would drift (DRY).
- **An allow case for a quoted read-only flag.** `git apply "--check" /tmp/p.diff` becomes allowed, because the shell passes `--check`. Alternative: keep denying it. That would deny a legal read-only command only because of its quotes.
- **cost-tiers.md location.** The review wait table goes under §5 directly after the execute wave wait table, in the same `| Knob | Default | Defined in |` shape. Alternative: a new section. The existing tuning tables all live in §5.
- **§6 third bullet unchanged.** The explore brief suggested adding `scripts/skill/*.js` and `scripts/state/*.js` to §6. Not done: it is outside the six items, and the bullet says "for example".

## Key Decisions

- **Amend existing ids, add none.** R90, R92 and R21 each get a clarified sentence and an appendix row with #9381. A new id would split one rule into two places.

- **Read arguments from masked word offsets.** The masked text and the real command have the same length, so the guard finds word boundaries in the masked text and copies each word from the real command by the same offsets. A quoted string with spaces then stays one word, as in the shell. Alternative: a full shell tokenizer. That is much more code for a best-effort filter (KISS).

- **The R90 threat model stays.** The guard stays a best-effort filter. Its accepted-gaps list does not change. Only the two named bypasses are closed.

- **Knobs named, values moved.** R21 and R92 name each flag and constant and point to `docs/cost-tiers.md` §5. The values move there. The code does not change.

- **Smallest viable cut.** One code task (the guard), one test-only task (ship), two spec tasks and one tuning-doc task. Each maps to one or two audit items.

**Non-goals (not built in this wave):**

- New guard bypass classes beyond F-77 and F-78; the R90 accepted gaps stay as they are.
- Any change to `ship.js` code; the plan-explore orchestrator (#9376); ship review counts (#9378); the lean orchestration skill.
- Value edits in user reference docs, SKILL.md or `wave-runner-template.md`.
- Any behavioural, headless or `claude -p` run.

**Who fails if this ships wrong?** Execute workers: a guard change that denies too much blocks their legal commands (exec runs, `cp`, validators) in every consumer project. Plan and review readers: a spec that loses a knob name leaves no pointer to the value.
