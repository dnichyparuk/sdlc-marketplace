## Context

**What problem does this change solve?**

- The specs (the behaviour contracts under `docs/specs/`) drifted from the code during M1–M5:
  - The ship spec does not describe the hook nudge dedupe (the hook sends each "step in progress" note once). It does not list the `warnings` output field. Its predicate text misses the `paused` early return.
  - The execute spec still names a compaction rule that was removed.
  - The review spec says the skill deletes a manifest that now persists.
  - Two specs (error-report, verify-pipeline) are still in the old "legacy" layout, so new ids cannot be added in the right section.
- Some text tells readers to do things the validators now reject: a `find` resolver, an EXIT trap. Some text describes removed features ("worktree mode").
- The execute skill parses the wave summary into a shell variable that nothing prints. So the context-overflow check never sees its input.

**What prompted this change now?**

- The arbiter placed W8.12–W8.20, #9172, #9180 and #9182 in M5.1 waves 4+5, joined into one branch (ruling join-4-5).
- The owner moved W8.32 (the prepare-line split) to its own wave 6 (ruling w4-w832-wave6). So this wave has 12 items.

**What does success look like?**

- The spec commits come first. P-5 prints `SAME` for both restructures, and exactly the ids each item names afterwards.
- `validate-spec-shape.js` no longer lists error-report-sdlc or verify-pipeline-sdlc.
- Every task's Verification passes as written. Each commit uses one wrapper call. `git status --porcelain` is empty after C-docs.
