## Context

**What problem does this change solve?**

- jira-sdlc tells the model to compute a `payload_hash`, write critique and approval files, and react to a PreToolUse hook. That hook was deleted. The spec (R21, G13, G15) already says so. The skill text, the operations reference, the docs and two test files still do not.
- The same MCP-failure procedure is copied five times in SKILL.md. Each copy uses shell variables (`$ANALYZE_JSON`, `$JIRA_SITE`, `$PROJECT_KEY`) that were set in an earlier Bash call. Each Bash call is its own shell, so those variables are empty at run time.
- Two `--load > "$JIRA_CONTEXT_FILE"` lines redirect into an unset variable. `jira.js` always prints a temp-file path, so even with the variable set the redirect would overwrite the context with a path.
- The model hand-builds the cache JSON and maps field types itself (Phase 6). This is deterministic work that belongs in the prepare script.
- Read-only operations (`search`, `view`) load about 2k tokens of write-pipeline text they never use.

**What prompted this change now?**

- Lean wave 4 of the sdlc plugin roadmap (tracking id #9344) bundles the jira-sdlc items W6a.1–W6a.5, #9189, the jira part of #9190, the jira part of W6c.10, and the PR #75 follow-up #9357.

**What does success look like?**

- No jira-sdlc skill file names `payload_hash`, `artifact-store`, `payload-hash`, `pre-tool-jira-write-guard`, `HOOK_COUNT` or `ANALYZE_JSON`.
- SKILL.md has one `### MCP-failure gate (R27, R28)` section. Four one-line references point at it.
- No SKILL.md, `write-ops.md` or `operations-reference.md` Bash block reads a `$VAR` that an earlier Bash call set.
- `jira.js --assemble` and `jira.js --check-payload` exist, with exec cases passing.
- All five main-session validators stay green.

**Who fails if this ships wrong?**

- Jira users of the plugin. A broken gate or approval step could dispatch a Jira write without approval, or lose MCP-failure telemetry. A wrong `--assemble` mapping corrupts the cached field schemas, and every later create or edit then fails with a 400.

## Decisions taken without the owner

No owner was available. Each choice below took the recommended or most conservative option.

1. **One SKILL.md task, not several.** All SKILL.md edits (W6a.1–W6a.5 parts, #9189, #9190, W6c.10) go in Task 6, a Complex task. The alternative was two or three serial SKILL.md tasks. One task saves one or two execute waves, and a single worker sees the whole file at once.
2. **Commit type `fix`.** The wave removes real runtime defects (#9190 empty variables, a stale hook path). `refactor` was the alternative.
3. **New P-ids P6, P7, P8.** Named ids such as `P-assemble` do not match the spec validator's id pattern; numeric ids continue P1–P5.
4. **`write-ops.md` holds the canonical eight-step procedure.** operations-reference.md keeps only a one-line pointer, so the procedure exists in one place.
5. **Tracking ids are not GitHub issues.** #9344, #9189, #9190 and #9357 are register ids. The PR body cites them as tracking ids and uses no `Fixes`/`Closes` keyword.
6. **No `--labels` flag** is added to `error-report-prepare.js`; the gate keeps the "labels `mcp-failure,class:<class>`" wording (definition guardrail).
7. **`--analyze --record` sends the telemetry block to stderr.** stdout stays one JSON line, so the existing `analyze outputs stable JSON shape` case keeps passing.

## Key Decisions

- **Scripts do the deterministic work.** The choice was between keeping the model's JSON-assembly and regex instructions, or moving them into `jira.js`. Scripts win: they are testable with exec cases, and they cost no model tokens (guardrail `scripts-over-llm-logic`).
- **One gate, one call.** The MCP-failure gate runs `mcp-failure.js --analyze --record`. The alternative was two calls (`--telemetry` then `--analyze`). One call removes the JSON-parse convention and the shared-variable problem.
- **Literal placeholders everywhere.** Every placeholder in a Bash block is written as `'<NAME>'` (a single-quoted literal the model substitutes) instead of `"$NAME"`. This matches the pattern already used in the Step 0 `--init-templates` block.
- **Two parallel test files.** New exec cases for `jira.js` go in a new dataset so the `mcp-failure.js` task and the `jira.js` task never edit the same file.
- **Smallest viable cut.** The minimum that removes the runtime defects is Tasks 1, 2, 6, 7. Tasks 3–5 and 8 are kept because they are named wave items (W6a.3–W6a.5) whose text Task 6 points to. Task 9 is a separate named item (#9357) with no shared files.
- **Workspace modes.** Nothing here writes state into the working tree. The Jira cache lives under `~/.sdlc-cache/jira/`, telemetry goes to `.sdlc/learnings/log.md` via `resolveSdlcRoot()` (the main worktree), and `--check-payload` reads template overrides from `resolveSdlcRoot()`. Behaviour is the same under `ship.workspace=branch` and `ship.workspace=worktree`.
- **No new state machine.** `--assemble --save` overwrites the cache file with the same bytes for the same input (apart from `lastUpdated`), like `--save` today. It sets no migration marker and no once-only state, so there is no transition to re-trigger; the existing `--check finds cache at home-cache layout after --save` case covers the read-back.

- **Cache-prompt stability.** No task adds volatile bytes (dates, run ids, paths) to SKILL.md or write-ops.md text.

**Non-goals (intentionally not built):**

- The GitHub-issues skill (wave 5), setup-sdlc (done in wave 3), and W6c.10 text rules for any other skill.
- W6c.10 sub-items 4 and 5 (`scripts/README.md`, `plugin.json`, `marketplace.json`).
- Deleting the orphan `tests/promptfoo/fixtures-fs/jira-hook-*` fixtures.
- Removing the `hook-block` class from `mcp-failure.js` (spec R26 requires all seven classes).
- Any headless, behavioural or `claude -p` run; any live Jira or Atlassian MCP call.
