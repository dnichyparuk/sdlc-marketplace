# Group E audit — commit-sdlc, pr-sdlc, version-sdlc, error-report-sdlc (+ orchestrators)

Audit date 2026-10-15. Plugin `sdlc` v0.21.29. Methodology: PROMPT-AUDIT-METHOD.md + PROMPTING-BEST-PRACTICES.md (2026-10-15 fetch).

**Step 0 assumptions.** Targets per BRIEF: `model: haiku` → Claude Haiku 5.5; `model: sonnet` → Claude Sonnet 5.5; unpinned reference files loaded by a pinned skill are audited against that skill's model. Provenance caveat: every file in this group shows as *Not Committed Yet* in `git blame` (large uncommitted working tree), so line-level provenance is unavailable; incident IDs embedded in the text (#198, #202, #211, #234, #347-349, #392, #398, #424, #485) were used instead.

**Pattern shared by the group.** Thin SKILL.md → prepare script (`scripts/skill/*.js`) → optional bounded orchestrator agent (haiku) → main-context approval gate → exact git/gh commands. The architecture is sound and matches current guidance (deterministic work in code, one judgment call on a cheap model, fragile ops as exact scripts). The findings below are mostly (a) stale facts the scripts contradict, (b) choreography and reminders carried over from older models, (c) missing effort/model tuning now that Haiku 5.5 and Sonnet 5.5 have effort levels.

## Group summary

**Overall rating: NEEDS-TUNING.** The architecture (prepare script → thin skill → bounded haiku orchestrator → main-context approval → exact git/gh commands) is aligned with current guidance and is the strongest part of the plugin. The findings are about residue, not design.

**Highest-impact findings (in order):**

1. **Frontmatter `model:` pins on commit-sdlc (haiku), version-sdlc (haiku), error-report-sdlc (sonnet), pr-sdlc (sonnet) contradict the plugin's own rule** (`docs/skill-best-practices.md:415`, error-report SKILL.md:182-184, commit SKILL.md:134): the pin routes the *entire parent transcript* into a subagent on the pinned model. On Haiku 5.5 this stacks the two documented long-prompt failure modes (early stopping, skipped verification) onto the skills whose correctness depends on verification gates (version-file one-line diff, stash/pop, tag conflict). The orchestrator pattern already provides the cheap-model routing for the judgment step; the skill-level pins should go. *High confidence, 4 files, one-line edits.*
2. **Two "load-bearing" claims in commit-sdlc that the script contradicts**: the post-generation `^wip(\(|:)` regex gate (:125-128) does not exist in `commit.js`; the "persistent manifest under `.sdlc/execution/`" (:44-47) does not exist in `lib/output.js`. The first means the only wip-prefix defense is the LLM reminder; the second is the stated reason commit-sdlc alone lacks the cleanup `trap`. *High confidence.*
3. **error-report-orchestrator reads the template from `PROJECT_ROOT`** (:44) — correct only inside this repository; every consumer project gets a missing-file read, and REFERENCE.md:85 gives a conflicting Glob-based location that the agent (Read-only) cannot execute.
