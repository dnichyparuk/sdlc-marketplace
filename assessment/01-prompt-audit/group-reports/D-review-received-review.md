# Group D audit — review-sdlc, review-orchestrator, received-review-sdlc

Audit date 2026-10-15. Plugin sdlc-utilities v0.21.29. Method: `PROMPT-AUDIT-METHOD.md` (groups 1a–1f, 2, 3, 4; keep list binding) + Anthropic "Prompting best practices" (2026-10-15 fetch).

**Target models (Step 0):** `review-sdlc` SKILL.md and `review-orchestrator` are pinned `model: sonnet` → Claude Sonnet 5.5. Dimension subagents run on each dimension's own `model:` (haiku / sonnet / opus → 5.5 generation) or `manifest.subagent_model` (hardcoded `sonnet` in review.js:638). `received-review-sdlc` is pinned `model: opus` → Claude Opus 5.5. REFERENCE.md section 2 (subagent prompt template) is therefore audited against all three 5.5 tiers; the orchestrator-facing parts against Sonnet 5.5.

**Environment note (not a repo finding):** this checkout has CRLF line endings on ~1,171 files. `scripts/lib/yaml.js:24` matches `^---\n…\n---` (LF only), so on this checkout `extractFrontmatter` returns `null` for every SKILL.md, agent, and `.sdlc/review-dimensions/*.md` — `validate-cost-tiers.js` reports every surface as INHERITED and `review.js` would fail to parse dimension frontmatter. HEAD is LF and parses. Worth one line in the cross-cutting report: the parsers should tolerate `\r\n` (`/^---\r?\n([\s\S]*?)\r?\n---/`) since Windows/WSL checkouts are a supported environment.

## Group summary

**Top findings, by impact**

1. **Subagent template vs `_common.md` contradiction (REFERENCE.md:208 vs EXAMPLES.md:403-409).** The one prompt every reviewer model receives says "do not read other files" while the shipped common prompt says "search the entire changeset, scan git history, flag when in doubt". Sonnet 5.5 takes the restriction literally and under-verifies; the "flag when in doubt" line turns the 20-finding cap into a quota. Fix: let reviewers read to *confirm*, report only in scope, and replace the quota-style line with a reportability bar. This is the single change most likely to raise review precision across all projects using the plugin.
2. **Tier doc drift and a dead CI check.** `docs/cost-tiers.md` says the review orchestrator runs opus; the agent runs sonnet (both at HEAD). The validator that is supposed to catch this reports INHERITED for every surface on CRLF checkouts (LF-only regex in `yaml.js`), and `review.js` cannot parse dimension frontmatter on such checkouts either. Fix the doc rows and make the frontmatter regex `\r?\n`-tolerant.
3. **Routing has no effort axis.** All cost control is tier-only; every sonnet dimension runs at Sonnet 5.5's `high` default, every opus/haiku one at `medium`. Adding an optional `effort:` per dimension (default medium) and re-tiering the three opus dimensions after a small eval is the main cost lever in this group. `dispatch-budget.js` still assumes 200K contexts (5× too small for the 5.5 generation).
4. **Deterministic rendering done by the LLM in the orchestrator.** Plan table, counts, verdict thresholds, §3 template fill and the summary block are fully determined by their inputs; moving them to a `review-consolidate.js` shortens every orchestrator turn, removes a class of "verdict not from counts" bugs, and leaves the model the dedupe/contradiction/calibration judgment it is actually there for.
5. **received-review-sdlc carries 2026-03-era anti-sycophancy and anti-narration scaffolding** (forbidden-opener list, four "process silently" banners, trust tiers, a critique-loop counter) plus ~1,100 words of duplicated R18/R25 matrix text, on the most expensive tier. The positive instructions and the reason already exist; keep those, drop the scaffolding, dedupe the matrices, and A/B Opus 5.5 `medium` against Sonnet 5.5 `high`. One stale flag (`--output-file`) in its prepare-script invocation needs verification.
