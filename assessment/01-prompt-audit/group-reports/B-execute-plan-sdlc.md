## plugins/sdlc-utilities/skills/execute-plan-sdlc/SKILL.md

**Summary.** Orchestrator for plan execution: loads/validates a plan, classifies tasks, builds waves, dispatches one wave-runner Agent per wave, verifies via `git diff`/canary grep, runs spec-compliance and guardrail checks, persists state through `scripts/state/execute.js`, recovers from failures, reports. Loads on skill trigger (user `/execute-plan-sdlc`, auto-trigger from plan acceptance, or dispatch from ship-sdlc). 1,020 lines / ~13,250 words (~18–20k tokens) read by Sonnet 5.5 every invocation.

**Assessment: NEEDS-REWORK.** The mechanics are sound and most of the length is genuine contract (state-script verbs, flags, manifest shape, resume rules) that the keep list protects. The problems are (a) a heavy layer of history narrative and spec/issue citations (`Fixes #392 / R35`, `R-WAVE-CONTEXT-PRODUCER, #506`) on nearly every paragraph — pure token cost and the Group 2 "history narratives" pattern; (b) the same rule restated 3–5 times in different sections (nested-dispatch block ×2, `model:` required ×4, no-`isolation` ×3, Edit-tool-only ×4 across the skill set), which makes the model spend effort reconciling wordings; (c) judgment steps written as rigid step choreography for Sonnet 5.5, which plans well on multistep agentic work; (d) a model-tier quality system (haiku/sonnet/opus presets, escalation chain) designed for the Claude 4 generation that the 5.5 generation's effort levels and per-token economics now undercut; (e) several volatile references that no longer resolve. Nothing here is unsafe; the surface is simply expensive and partly fossilized.

### Efficiency & cost notes
- **Load cost:** ~19k tokens of SKILL.md per invocation, plus ~6k for classifying.md (always read at Step 2) plus ~4k wave-runner-template.md per wave dispatch plus the per-task template (~2.3k) and batched template (~2.2k) inlined into *every* wave-runner prompt. For a 4-wave plan: ~19k + 6k + 4×(4k + 2.3k + 2.2k + manifest) ≈ 60k tokens of instruction text before any code is read.
- **Progressive disclosure is partly done right** (recovering-from-failures.md read on failure only; state-format.md on resume only). Candidates to move out of SKILL.md into on-demand files: OpenSpec flip/archival (lines 62-64, 657-689, 954-1007 ≈ 2.5k tokens, only when `**Source:**` points at openspec), `--commit-waves` (569-600), post-compact discriminator (133-151).
- **Model tier:** orchestrator at Sonnet 5.5 is right (multistep tool use is its strength). Workers: see B2/B14 — two tiers + effort beat three tiers. Spec reviewer at Sonnet 5.5 is right.
- **Deterministic work done by LLM:** Contract/Notes block extraction from plan markdown (395-401), task-ID JSON array assembly, `expectedFiles` union (classifying 6b says "No LLM inference" yet the orchestrator computes it by hand — no script verb exists), wave manifest JSON assembly, guardrail JSON passthrough, `git merge-base` reachability loop (107-112). All are candidates for a `build-waves` / `emit-manifest` verb on `state/execute.js`, which would also remove the biggest source of transcription errors.
- **Caching:** the per-task template's guardrail block is correctly placed first and byte-stable (good). The orchestrator's own prompt is not cacheable across waves because each wave appends new tool output; acceptable.

## Group summary

**Overall rating: NEEDS-REWORK** (SKILL.md) / NEEDS-TUNING (classifying, wave-runner, spec-reviewer) / GOOD (recovering, state-format).

**Highest-impact findings:**

1. **Model-tier presets are calibrated for the Claude 4 generation (B2, B14, B27, B29, B35, B39).** The haiku/sonnet/opus ladder was built when Opus was 2.5× Sonnet's price and Haiku was a safe executor for small coding tasks. On the 5.5 generation Opus 5.5 is $4/$20, Sonnet 5.5 at `medium` beats Sonnet 5 at `high` at a fifth of the cost, and Haiku 5.5 is documented to stop early and skip verification in long agent prompts — exactly the shape of the per-task worker prompt. Worst case today: an all-Trivial wave puts the wave-runner itself (deadline enforcer, JSON contract emitter) on Haiku 5.5. `dispatch-budget.js` also still assumes a 200K context ("Claude 4 family"), so wave sizes are 5× more conservative than the 1M-context 5.5 models need. Recommended re-baseline: two tiers (Sonnet 5.5 / Opus 5.5) with effort as the speed/quality knob where Claude Code exposes it on dispatch, Haiku only for batched trivials with the Haiku 5.5 verification + keep-going paragraphs added, runner floor Sonnet 5.5. Measure cost per completed plan, not per token.

2. **Worker prompts lack the documented 5.5-generation verification instruction and contain tool-use discouragement (B23, B26, B24).** The per-task and batched templates never tell the worker to run a real check before reporting done (both Sonnet 5.5 and Haiku 5.5 have this documented gap at low effort), while they *do* tell it not to search for a missing upstream surface — Sonnet 5.5 follows that literally, producing avoidable NEEDS_CONTEXT round-trips that each cost a re-dispatch at the next tier. Cheapest, highest-return edit in the group: ~8 lines added, ~2 lines changed.

3. **Stale-contract contradictions that cost tokens or produce wrong behaviour (B1, B9/B10, B15/B31/B46, B17, B40, B43).** A non-existent `hooks/context-stats.js`/`UserPromptSubmit` mechanism; the DO-NOT list and Gotchas still say "paste the full task text" while the fact-sheet design forbids it; `attempts[]` is both required and banned in the wave-runner file; `--run-id` is forbidden in SKILL.md and described as passed in two reference files; the `parseWaveSummary` bash block ships in a form the next line says not to run; the error-report lookup globs `~/.claude/plugins` (may hit another installed version) instead of `<PLUGIN_ROOT>`; the reviewer template names the old `Task` tool.

4. **Repetition and archaeology (B3, B4, B5, B16, B22, B30, B33, B34, B38).** Six rules (nested dispatch, `model:` required, no `isolation`, Edit-tool-only, guardrail threading, don't-trust-reports) appear 3–6 times each across the files, mostly with `Fixes #NNN` tags and escalating CAPS. On Sonnet 5.5 the repetition buys nothing and the register bleeds into output. Estimated saving ≈ 4–5k tokens per invocation plus ~1k per wave, with no loss of contract if each rule is stated once with its reason.

5. **Deterministic work left to the orchestrator LLM (B13, B18, B20, classifying 6b).** Plan-markdown field extraction, manifest JSON assembly, `expectedFiles` union, workspace derivation, and the post-compact signal discriminator are all input-determined. A `build-waves` / `emit-manifest` verb on `state/execute.js` would remove the largest transcription-error surface and several hundred lines of prose; the LLM-judgment calls that should remain are task classification, the inter-wave drift critique (5e), and post-wave guardrail evaluation.
