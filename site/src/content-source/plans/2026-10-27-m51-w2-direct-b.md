## Key Decisions

1. **D1 quotes code fragments, not the whole message line.** The shipped message is built from several string pieces on separate code lines, so the gate grep checks four fragments that each sit on one code line. The doc keeps the existing message block byte-identical (the base text is unchanged in code) and adds one sentence plus a fenced line with the new suffix.
2. **Guard placement.** The two lines go directly after the first line that starts with `set -e` (also `set -euo pipefail`); in a file without one, directly after the shebang (line 1). The guard therefore precedes the first git command and, in `tag-exists`, the `rm -rf .git`. The 7 files with an earlier "git" comment are fine: comments run nothing.
3. **What the check script checks.**
   - Part (i), the default: for each `setup.sh` under `tests/promptfoo/fixtures-fs/`, at any depth, that contains `git init` or `git config`, the guard's `if git rev-parse --show-toplevel …; fi` line must come before the first non-comment line containing `git init` or `git config`.
   - Part (ii), `--probe`: it creates `<tmp>/repo` with `git init -q`, copies the guarded fixture `project-execute-prepare` to `<tmp>/repo/fx` and runs its `setup.sh` there. It reports the exit code, stderr and whether `<tmp>/repo/.git/config` changed, then removes `<tmp>`.
4. **Behavioural case (D-beh): none.**

**Non-goals:** no other line of any `setup.sh`; no fixture content file; `extract-skill-content.js`, the providers and every other `docs/skills/` page unchanged.

**Failure audience:** ship-sdlc users reading the skill doc (D1); anyone who runs the promptfoo suites or a fixture `setup.sh` from inside a linked worktree (D2).
