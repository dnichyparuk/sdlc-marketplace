## Context

**What problem does this change solve?**

- 40 lines in the skills read like `VAR=$(node "<PLUGIN_ROOT>/scripts/…" …)`. A headless run with `--permission-mode dontAsk` denies such compound lines even with a `Bash(node:*)` allowlist, so every headless eval case needed an auto-mode re-run (todo #9168; M5 eval: 4 of 4 runs).
- Each Bash call is its own shell. So a shell variable set in one call is empty in the next. Two skills depend on that today and silently lose data:
  - harden: `CONTENT_ROOT` is set in Step 3 and read in Step 5b, so the `_common.md` check never finds the file;
  - setup-dimensions: `COMMON_CONTENT` is set in step 1 and piped in step 3, so the common prompt is never injected.

**What prompted this change now?**

- The owner chose "Rewrite all 40 now" and moved W8.32 into its own wave (`owner-q25.md`; ruling w4-w832-wave6).
- Ruling w6-preflight settled the ten pre-flight questions (Q1–Q10).

**What does success look like?**

- `grep -rn '=\$(node' plugins/sdlc-utilities/skills/` prints nothing (68 files scanned).
- Every Bash call the touched blocks prescribe is one plain command: no `VAR=$(…)`, no `;`, no `&&`, no pipe. The skill reads the path or value and the exit code from the tool result.
- The user sees the same messages: the pr recovery line, the jira dispatch gate at count 2, the harden and setup mirrors (now with the common prompt).
- check-consistency stays green with no validator edit; both full exec configs pass at the final head (983 / 58).
